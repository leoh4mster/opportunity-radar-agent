# 可观测性与故障定位

## 能看到什么

每个 HTTP 请求都会获得 `X-Request-ID`。调用方传入的 ID 仅在匹配 `[A-Za-z0-9._:-]{1,80}` 时沿用，否则服务端生成 32 位随机 ID。响应头返回同一个 ID；未处理的 500 响应也在结构化错误体中返回它，因此前端报错、API 响应和后端日志可以串起来。

默认日志是单行 JSON，包含 UTC 时间、级别、模块、事件、请求 ID、路由模板、状态码和耗时。慢请求阈值默认 1000 ms。访问日志只记录路由模板，不记录请求正文、查询参数、请求头、模型提示词或 API Key；Uvicorn 和 httpx 的原始 URL 访问日志被关闭。异常在 INFO/WARNING/ERROR 下只记录类型，完整堆栈仅在主动把 `LOG_LEVEL` 设为 `DEBUG` 时输出。已有业务日志可能包含文章标题、数据库 ID 或搜索词，公开部署前仍应做统一数据分级与脱敏审计。

LLM Gateway 记录逻辑调用、实际尝试、重试后的最终结果、错误类型和耗时区间。无 Key 使用本地规则，以及远程抽取/推荐失败后的回退，会按任务和原因计数。指标不会保存提示词、响应文本、凭据或模型供应商错误正文。

## 查看方式

- 前端「总览 → 工程运行状态（面试演示）」：显示 API 请求、4xx/5xx、远程模型调用、本地回退和最慢路由。
- `GET /observability/metrics`：返回完整 JSON 快照。
- 运行后端的终端：查看逐行 JSON 日志。
- API 错误响应/响应头：复制 `X-Request-ID` 检索对应日志。

本地配置写在未提交的 `.env`：

```text
LOG_LEVEL=INFO
LOG_FORMAT=json
SLOW_REQUEST_MS=1000
```

调试时可临时改为 `LOG_FORMAT=text` 或 `LOG_LEVEL=DEBUG`，改完重启后端。不要把含个人数据的调试日志提交 Git。

## 指标语义和边界

指标存在后端内存中，作用域明确标为 `single_process`，重启清零，不进入 SQLite，也不影响用户数据。时间直方图使用固定毫秒区间；HTTP 按方法和 FastAPI 路由模板聚合，未知路由统一为 `__unmatched__`，不会把用户 ID 或 URL 参数变成标签。指标接口本身不计入请求统计，避免刷新页面污染结果。

这是适合本地演示和单进程诊断的轻量方案，不是生产监控平台：

- 多 worker 时各进程指标独立，不能直接相加当作全局真值。
- 没有持久化、跨服务 trace、告警、token 数量或成本统计。
- 指标接口当前没有鉴权，只适用于绑定 `127.0.0.1` 的本地应用；部署公网前必须增加身份验证或只允许内部网络访问。
- 模型供应商当前响应格式没有稳定提供/保存 token usage，因此不能编造费用数字。

产品化时可把同一事件和字段映射到 OpenTelemetry，将指标导出 Prometheus/Grafana，并接入日志聚合与告警。届时仍应保留低基数路由标签和数据最小化原则。
