# 导入可靠性与抽取评测

## 业务闭环回归（2026-09-26）

本地测试已从 54 项扩展到 99 项，新增覆盖：

- 本地规则检查不能写入真实核验状态、占位证据或伪造可信度分数；原文链接不会直接变成官网或报名入口。
- 旧工具入口与机会 action 共用实际待办、日历服务；待办、状态、行为和工具日志失败时回滚。
- 机会总待办与计划子任务具有独立身份；重复同步不新增，批次失败不留下部分子任务。
- 开启外键约束后删除完整文章或用户关联图，以及删除中途失败后的恢复。
- 模型数值范围、有限值、字符串类型、必填字段和摘要质量校验；合法的 0 分不会被默认值覆盖。
- 新成长记忆进入增强推荐上下文，用户间记忆隔离；明确反馈文本保留；负反馈影响规则分数。
- Streamlit 标注控件不预填模型答案、不把“尚未判断”当 0 分，切换记录不串用判断。
- 用户确认计划变更时同步关联子待办，身份不匹配拒绝修改，版本保存失败整批回滚；记忆包含计划风险并按提示词版本刷新；已加载推荐再次生成无对象身份冲突。
- 无网络 API 端到端流程：创建画像、上传文章、抽取、推荐、待办、日历、反馈、删除。

所有新增业务和 UI 测试使用隔离数据。真实 API 的虚构服务链验收另由 `evaluation.check_agent_live --allow-network` 显式触发，不在默认测试和 CI 中运行。模型真实语料效果、可靠后台任务、Collector 与公网权限体系仍是后续工作；不能由测试数量推导真实准确率。

## 浏览器导入

左侧「导入文章」支持上传 UTF-8 JSON / TXT / Markdown（含 UTF-8 BOM）。
单次文件上限 2 MiB、500 篇。上传文件以字节流解析，不使用客户端文件名写入服务器文件系统。
成功后显示新增数和重复数；再点击「处理未抽取文章」进行抽取。

JSON 支持单对象、数组或 `{"articles": [...]}`：

```json
{
  "articles": [
    {
      "title": "数据分析实习招募",
      "content": "欢迎申请。\n地点：上海\n报名截止：2030-12-31",
      "source": "个人整理",
      "url": "https://example.com/apply"
    }
  ]
}
```

API：`POST /articles/upload`，multipart 字段为 `file`。
响应沿用 `imported`、`skipped_duplicates`、`article_ids`。
非法格式、正文为空、编码错误返回 400；文件超过上限返回 413。
已有本地路径导入 API 保留，使用同一解析器与校验规则。

## 导入事务与身份

- 完整校验一批文章后才开始写入；存储失败时回滚整批。
- 正文去除空白后计算 SHA-256。同一批、重复上传、路径导入和采集入口使用相同规则。
- 采集接口仍接收 `content_hash` 以兼容旧客户端，但正文身份只由服务端计算。错误哈希不会绕过去重。
- 采集入库与机会抽取在同一事务，抽取失败不留下孤立的新文章。

正文 SHA-256 现已持久化为 `articles.content_hash`，设有非空和数据库唯一约束。导入不再扫描全部旧正文：尝试插入，冲突时按哈希查回已有记录。批量上传、路径导入、采集接口共用插入逻辑。

SQLite 保存点外显式开启事务，防止 Python sqlite3 旧事务模式提前提交部分批次。重复冲突只回滚保存点；其他存储异常仍回滚整批。文件数据库测试使用独立连接，8 个并发上传/采集请求只产生一篇文章；8 个并发采集请求只抽取一次。

边界：这是数据库内的文章唯一性，不是任意外部动作的“恰好一次”执行保证，也不保证 `/pipeline/process` 的并发抽取幂等性。SQLite 仍是单写者；采集抽取目前位于写事务内，远程模型慢时可能延长锁等待，超过等待上限仍可能失败，需要后续任务队列改造。删除所有空白的 v1 规则也可能合并语义不同的英文内容，不能在没有数据迁移的情况下直接换哈希规则。直接执行原生 SQL 的维护者须自行保证哈希与正文一致；业务 API 和 ORM 写入由服务端计算。

旧库升级、历史重复记录策略和备份恢复见 [DATABASE.md](DATABASE.md)。

## 可复现评测

```bash
cd opportunity-radar-agent
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m evaluation.run
python -m evaluation.run --check
```

`evaluation/cases.json` 包含 15 条手写合成用例，10 条机会、5 条非机会。
覆盖实习、竞赛、实验室、科研、讲座、夏令营、奖学金、课程、交流，包含取消通知、活动回顾和经验文章。
每条最多标注一个机会；没有覆盖一文多机会、真实用户偏好排序或大规模中文语料。

评测强制注入离线 gateway，即使本机配置了真实 API Key 也不会调用模型，不产生 API 费用。
`--check` 对照 `baseline.json` 的最低指标，下降时返回非零退出码；CI 自动执行。

| 指标 | 初始结果 | 定义 |
| --- | --- | --- |
| Precision | 0.7692 | 正确识别数 / 预测机会数，10 / 13 |
| Recall | 1.0000 | 正确识别数 / 标注机会数，10 / 10 |
| F1 | 0.8696 | Precision 与 Recall 的调和平均 |
| 字段精确匹配率 | 0.9750 | 正例中类别、日期、地点、链接匹配字段数，39 / 40 |

字段匹配率含预期空值，不计负例上的多余字段；它不能代替 Precision。
报告输出失败用例 ID 和失败字段。上表为初始基线；2026-09-26 修复叙述日期与机会/资讯边界后，该合成集 F1 1.0、字段 40/40，无失败案例。
这些数值只描述这份小型合成回归集，不能写成真实业务准确率，也不是 DeepSeek 的模型效果。
后续应收集独立标注的真实文章与保留测试集，再做规则与模型对比。

真实数据闭环的导出、人工标注、数据指纹、多机会匹配和推荐排序指标已经实现，详见 [EVALUATION.md](EVALUATION.md)。本机已在私有 review 目录完成 9 篇抽取、1 组排序的首次人工确认并生成规则指标；仓库中的三组排序案例仍是虚构 CI 回归集。

## API 回归测试

API 测试使用内存 SQLite 并覆盖依赖，不启动生产数据库 lifespan；显式禁止外部模型调用。
覆盖错误哈希去重、跨入口幂等、批次校验失败、存储异常回滚、抽取异常回滚、大小和数量边界、UTF-8 BOM。

另有临时文件 SQLite 的并发与迁移测试，覆盖真实多连接请求、保存点释放后整批回滚、空库初始化、旧库数据与外键保留、WAL 一致性备份、重复数据阻断、并发启动升级、版本回退再升级，以及 ORM 与迁移结构一致性。这些测试同样不会连接真实模型或修改个人数据库。
